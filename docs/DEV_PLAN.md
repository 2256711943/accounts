## 0. 使用说明

### 0.1 每日节奏（建议）

| 时段 | 内容 |
|---|---|
| 09:00–09:20 | 过一遍昨日 DoD，确认没欠账；看一眼今日目标 |
| 09:20–12:00 | 主任务 A（通常是当天最难的 1 件事） |
| 14:00–17:30 | 主任务 B + 自测 |
| 17:30–18:00 | **收尾三件事**：跑通双端 → 提交 Git → 写今日「简历产出」一行 |

### 0.2 铁的纪律

1. **每天必须双端（小程序 + H5）都能跑**。任何一天只在一端能跑，视为当天未完成。
2. **每天必须有 Git 提交**，提交信息用 `feat/fix/perf/docs` 前缀。
3. **不写没有验证过的功能**。写完立刻在真机（微信开发者工具 + 手机预览）过一遍。
4. **亮点优先于功能**。工期不够时，先砍业务功能（F6–F9），再砍 H4，最后才砍 H3。**H1、H2 不可砍**。
5. **每天结束时写一行「今天能写进简历的句子」**。写不出来的那天，说明在做无价值的活。

### 0.3 里程碑与止损点

| 里程碑 | 时间 | 判定标准 | 未达成怎么办 |
|---|---|---|---|
| M1 设计定稿 + 组件层就绪 | D3 结束 | Figma 5 个页面 + 组件齐全，tokens 已生成 SCSS，**组件库主题映射验证通过** | 砍 `04 Prototype`，只保留静态稿；映射失败的单个组件退回自研（不影响里程碑判定） |
