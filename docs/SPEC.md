## 1. 项目定位

### 1.1 一句话定义
一个**拍照即记账**的跨端小程序：拍一张小票或说一句话，自动识别成结构化账单，本地先落库、联网再同步，首页给出月度消费画像。

### 1.2 这个项目的真实目的（重要，决定一切取舍）

这是一个**简历导向型项目**，不是商业产品。它的第一目标是补齐简历上「移动端 / H5 / 小程序」的能力空缺，第二目标才是做出一个能用的记账工具。

因此本项目的**取舍原则**：

| 优先级 | 内容 | 说明 |
|---|---|---|
| P0 | 能写出**技术机制 + 可复现数字**的亮点 | 与既有简历「帧缓冲 / 断点续跑 / 虚拟滚动压测」的叙事风格一致 |
| P1 | 双端（微信小程序 + H5）都能跑通 | 「跨端」这件事必须有证据，不能只跑一端 |
| P2 | 业务闭环完整（能记、能看、能改、能删） | 没有闭环的技术点是空中楼阁 |
| P3 | 业务功能丰富度 | **主动放弃**：多账本、预算体系、导出、社交、支付 |

> ⚠️ 反模式：如果最后交付的成果只能写出「使用 uni-app 开发了一款记账小程序，实现了登录、列表、图表功能」，这个项目就是失败的，属于负资产。

**组件来源原则**（决定 UI 层怎么写，与 `ARCHITECTURE.md` §1.2 一致）：

| 类型 | 处理 | 组件 |
|---|---|---|
| **交互密集型** —— 价值在边界处理（浮层 / 手势 / 滚动穿透 / 键盘避让 / 选择器） | **外采** `wot-design-uni` 1.14.0，easycom 按需引入 | `datetime-picker`、`action-sheet`、`popup`、`message-box`、`toast`、`img`、`swipe-action`(可选)、`switch`、`loadmore`、`number-keyboard` |
| **视觉密集型** —— 构成页面气质（色 / 圆角 / 字阶 / 留白） | **自研** | `Button`、`Cell`、`Card`、`Tag`、`Avatar`、`Skeleton`、`Empty` |
| **简历亮点本体** | **一律自研，禁止外采** | `DonutChart`（canvas 2d 自绘）、虚拟列表 |

判定口径只有一句：**价值在"交互复杂度"就外采，价值在"视觉表达"就自研。**

外采组件**不采用其默认视觉**——通过 `src/styles/wot-theme.scss` 把 Design Token 映射到组件库的 `--wot-*` CSS 变量（映射表见 `UI_SPEC.md` §4.3，机制见 `ARCHITECTURE.md` §3.5）。**禁止**在页面里直接使用未做主题映射的组件库组件。

### 1.3 目标用户与核心场景

| 场景 | 用户行为 | 痛点 | 我们的解法 |
|---|---|---|---|
| 外卖/超市小票 | 拍一张 | 手动输金额、挑分类太麻烦 | 拍照 → OCR → 自动填金额/商家/分类 |
| 脑子里一闪而过的支出 | 语音说一句 | 打开 App 到输完要 5 步 | 一句话 → 规则解析 → 直接落库 |
| 地铁里没信号 | 记一笔 | 弱网转圈、失败重试丢数据 | 本地先落库，联网自动补传 |
| 月底想复盘 | 打开首页 | 数据散乱看不出结构 | 月度汇总 + 分类占比环图 |

## 3. 功能范围

### 3.1 MVP（必须做，D1–D9）

**F1 拍照识别记账**
- 用户可拍照或从相册选图（单张）
- 图片在端内压缩后上传，识别出：金额、商家、分类、时间、备注
- 识别结果以"确认卡"形式呈现，字段可编辑后再保存
- 识别失败/超时降级为手动填写，不阻塞记账

**F2 账单列表与详情**
- 首页按时间倒序展示账单，支持下拉刷新、上拉加载更多
- 点击进入详情，可修改金额/分类/备注/时间，可删除
- 支持按分类筛选（分类为水平滚动标签条）

**F3 月度统计**
- 本月总支出、日均支出、环比
- 分类占比环形图（canvas 2d 自绘）
- 分类明细列表（金额 + 占比 + 笔数）

**F4 我的**
- 登录状态展示（小程序走云开发 openid，H5 走设备匿名 ID）
- 隐私授权设置入口、清理缓存
- 开发面板（隐藏入口：连续点击版本号 5 次）展示性能指标

**F5 离线优先**
- 断网状态下仍可新增 / 修改 / 删除账单
- 联网后自动同步，不产生重复数据
- 同步状态可视化（待同步 / 同步中 / 已同步 / 失败可重试）

### 3.2 加分项（D10–D13 择二）

- **F6 语音记账**：录音 → 上传 → 解析"金额 + 分类关键词"，走与拍照同一套识别管线
- **F7 每日记账提醒**：云函数定时触发器 + 订阅消息（记账后申请一次订阅额度，24h 未记账则提醒）
- **F8 识别纠错回流**：用户手动改正的字段写入 `correction` 集合，作为分类规则的本地学习样本
- **F9 分享卡片**：canvas 生成月度账单分享图（学到 canvas 合成 + 保存到相册 + 权限处理）

### 3.3 明确不做（Out of Scope）

多账本、预算与超支预警、账单导出（CSV/Excel）、社交与好友、微信支付、会员体系、后端管理后台、App 端打包。

## 4. 用户故事与验收标准

| ID | 用户故事 | 验收标准（Given / When / Then） |
|---|---|---|
| US-01 | 我想拍张照就记一笔账 | Given 已授权相机，When 拍照并等待识别，Then 3 秒内出现确认卡且金额字段已填充；若超时 8 秒，Then 降级为手动填写表单并提示 |
| US-02 | 我希望断网也能记账 | Given 已断网，When 新增/修改/删除账单，Then 操作立即生效并标记"待同步"；恢复网络后 5 秒内自动同步完成，账本数量与服务端一致且无重复 |
| US-03 | 我想知道钱花在哪了 | Given 本月有 ≥1 笔账单，When 打开统计页，Then 展示总额、环图、分类明细，环图占比之和为 100% |
| US-04 | 我要改掉识别错误的分类 | Given 在详情页修改分类，When 保存，Then 列表与统计同步更新；该笔的修正记录写入纠错集合 |
| US-05 | 我希望能用手机浏览器看 | Given 打开 H5 地址，When 完成一次记账全流程，Then 与小程序端表现一致（含空态、加载态、错误态） |
| US-06 | 我希望首屏快 | Given 冷启动，When 进入首页，Then 首屏内容 ≤1.2s 可见（缓存直出），主包体积 ≤1.5MB |

## 5. 数据模型

### 5.1 records（账单，云数据库集合）

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 云端生成 |
| `clientId` | string | **客户端生成 uuid，唯一索引，幂等键** |
| `_openid` | string | 云开发自动注入，数据隔离依据 |
| `type` | `'expense' \| 'income'` | 默认 expense |
| `amount` | number | 单位「分」，整数，避免浮点误差 |
| `categoryId` | string | 分类 id |
| `merchant` | string | 商家名，可空 |
| `remark` | string | 备注，≤100 字 |
| `happenedAt` | number | 账单发生时间戳（ms） |
| `source` | `'photo' \| 'voice' \| 'manual'` | 录入来源，用于埋点分析 |
| `recognizeMeta` | object | `{ engine, confidence, costMs, degraded }` |
| `imageFileId` | string | 云存储 fileID，可空（手动记账无图） |
| `deleted` | boolean | 软删除标记 |
| `createdAt` / `updatedAt` | number | 时间戳 |
| `version` | number | 乐观并发控制用，每次修改 +1 |

索引：`clientId` 唯一索引 ｜ `_openid + happenedAt` 复合索引 ｜ `_openid + deleted + happenedAt` 查询索引

### 5.2 categories（分类）

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` / `key` | string | 内置分类用固定 key（food/transport/shopping/…） |
| `name` / `icon` / `color` | string | 展示信息 |
| `sort` | number | 排序 |

内置 10 个支出分类 + 4 个收入分类，随 app 版本内置在前端常量里（避免首屏依赖网络），纠错回流只影响前端规则表。

### 5.3 user_settings（用户设置）

`_openid`、`deviceId`(H5)、`remindEnabled`、`budgetNote`、`perfUploadEnabled`、`createdAt`

### 5.4 perf_logs（性能埋点）

`_openid`、`sessionId`、`metric`(launch_t1/t1/t2/setdata/api/error)、`value`、`page`、`payload`、`ts`

### 5.5 correction_logs（识别纠错）

`_openid`、`recordId`、`field`、`before`、`after`、`ts`

## 6. 非功能需求

### 6.1 性能指标（必须实测并留档）

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 主包体积 | ≤ 1.5 MB | 微信开发者工具「代码依赖分析」 |
| 组件库增量体积 | ≤ 150 KB（计入主包） | 引入前 / 后各跑一次依赖分析，取主包差值 |
| 整包体积 | ≤ 3 MB | 同上 |
| 冷启动 T1（onLaunch→首页 onReady） | ≤ 1.2 s，二次启动 ≤ 0.6 s | 自研埋点 + 开发者工具性能面板 |
| 列表性能 | 5000 条数据滚动不掉帧、DOM/节点数 ≤ 200 | 自研埋点记录可视节点数 + 体验评分 |
| setData 单次数据量 | 长列表滚动中 ≤ 8 KB/次 | 重写 setData 统计 |
| 图片压缩 | 4 MB 原图 → ≤ 200 KB，耗时 ≤ 800 ms | 端内埋点 |
| 首屏接口 | 缓存直出 + 静默刷新，无白屏 | 录屏 |

### 6.2 兼容性

- 微信基础库 ≥ 2.30.0；iOS 14+ / Android 8+
- H5：iOS Safari 14+、Android Chrome 90+、桌面 Chrome/Edge 最新版
- H5 宽屏：内容区最大宽度 480px 居中，超宽屏不拉伸变形

### 6.3 合规与安全

- **隐私合规**：配置《用户隐私保护指引》，调用相机/相册/剪贴板前处理授权；拒绝授权后走手动录入降级路径（不得卡死）
- **数据隔离**：所有数据读写经云函数，云函数内强制以 `cloud.getWXContext().OPENID` 注入查询条件，客户端不可传 `_openid`
- **金额安全**：金额以「分」为整数存储，前端只做展示层格式化，杜绝浮点累加
- **入参校验**：云函数对所有入参做类型 + 范围校验，非法参数直接拒绝
- **无密钥硬编码**：模型 API Key 只存在于云函数环境变量

### 6.4 可维护性

- TypeScript 严格模式，`strict: true`，禁止 `any` 逃逸
- 端到端类型：云函数入参出参共用 `src/types/api.ts` 一份定义
- Git 提交遵循 `feat/fix/perf/docs/refactor` 约定；每个里程碑打 tag

## 7. 度量与验证方案（简历数字从哪来）

> 原则：**不编造数字，每个数字都要有可复现的测量脚本或截图**。

| 亮点 | 测量方法 | 产出数据 |
|---|---|---|
| 图片压缩管线 | 端内埋点记录 `originalSize / compressedSize / costMs / uploadMs`，跑 20 张不同尺寸样本 | 压缩比、平均耗时、上传耗时下降 % |
| 虚拟列表 | 用脚本灌 5000 条数据，埋点记录可视节点数、setData 次数与数据量、滚动中长任务时长 | 节点数、setData KB、FPS 采样 |
| 离线同步 | 飞行模式操作 10 笔（含增删改），恢复网络后统计同步成功率与重复率 | 同步成功率 100%、重复记录 0 |
| 包体积/启动 | 关闭/开启分包优化各测一次，记录主包体积与 T1 | 主包从 X MB → Y MB、T1 降低 % |
| 跨端一致 | 同一份数据在小程序与 H5 分别截图对照 | 双端对照图 |
| 组件库主题桥接 | ① 改 `tokens.json` 的 `color/accent` → 跑 `gen:scss` → 双端确认 `wd-*` 组件主色同步；② 引前/引后各跑一次代码依赖分析 | 主包增量 KB、双端主题一致性截图 |
| 组件库取舍论证 | 记录引入的组件数与 token 数、砍掉的组件及原因 | 一张"引入清单 + 体积账"表 |

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 小程序域名备案周期长 | 阻塞上线 | 走微信云开发，小程序端用 `callFunction` 免域名配置；H5 端走云函数 HTTP 访问服务 |
| 个人主体小程序能力受限 | 部分功能做不了 | **不做支付**；订阅消息用一次性订阅；若类目审核不过，交付形态改为「体验版 + 录屏 + GitHub 源码」 |
| 多模态识别成本/时延不可控 | 影响体验与预算 | 分级识别：本地规则优先，云端兜底，8s 超时降级；模型调用做结果缓存 |
| 15 天工期紧 | 亮点做不完 | 亮点按 H1→H4 优先级排序，工期超支时砍 F6–F9，绝不砍 H1/H2 |
| 云开发在 uni-app 中接入有坑 | 阻塞 D4 | D4 设为止损点：若 4 小时内跑不通，立刻切备选方案（自建 NestJS + 云函数代理，或全前端 mock + 本地持久化），架构文档已预留切换路径 |
| 组件库默认视觉与设计稿冲突 | 页面出现两套风格，设计稿白做 | 主题变量桥接（一级 + 二级映射）；D3 验收方式：改 token 后 `wd-*` 主色必须同步变化；仍不一致的组件退回自研 |
| 组件库增量挤爆主包预算 | 主包 >1.5MB | easycom 按需引入；超预算按 `ARCHITECTURE.md` §1.2「外采」清单从后往前砍（先 `wd-swipe-action` / `wd-number-keyboard`） |
| 组件库主题映射在小程序端不生效 | 双端视觉不一致 | 退到 `wd-config-provider` 的 `theme-vars` + `@uni-ku/root`；仍不行则该组件退回自研（只影响单个组件） |
